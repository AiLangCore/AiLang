# AiLang Optimization Pipeline

Status: normative compiler pipeline direction.

AiLang optimization must preserve deterministic semantics defined by
`SPEC/IL.md`, `SPEC/EVAL.md`, `SPEC/VALIDATION.md`, and `SPEC/BYTECODE.md`.
No optimization may depend on host timing, pointer identity, thread scheduling,
filesystem ordering, network state, or target-specific undefined behavior.

## Pipeline

The self-hosted compiler pipeline is:

```text
Parser
  -> AST / IL nodes
Semantic validation
  -> checked IR
Local optimization
  -> AiBC object
Linker
  -> linked program graph
Whole-program optimization
  -> final AiBC bundle
Publish target
```

## Local Optimization

Local optimization runs before object emission and may only use information
inside the current module or function unless the dependency is explicitly part
of the checked IR.

Allowed local optimizations:

- constant folding
- constant propagation
- dead code elimination within a function
- peephole optimization
- deterministic inlining where specified
- strength reduction
- canonical instruction selection

Local optimization must emit the same observable behavior and diagnostics as
the unoptimized checked IR.

## Linker

The linker consumes deterministic AiBCO1 module objects and emits the final
AiBC1 program. See `SPEC/AIBCO.md` for object, symbol, and relocation rules.

The linker owns deterministic module graph construction and final program
assembly. It must:

- start from `Project.entryFile` and `Project.entryExport`
- resolve imports in deterministic order
- reject circular imports deterministically
- include only reachable modules, symbols, assets, and package dependencies
- emit a link report before final bundle emission

The current linker milestone includes deterministic module path collection,
package-root-aware import resolution through `ailang.lock.toml`,
circular-import diagnostics, linked bundle description emission, and link report
emission. Symbol reachability, asset reachability, package dependency pruning,
and final AiBC binary emission remain follow-up linker/compiler
responsibilities.

## Whole-Program Optimization

Whole-program optimization runs after link graph construction. It may use
cross-module reachability and final call graph information.

Allowed whole-program optimizations:

- cross-module dead code elimination
- deterministic inlining across module boundaries
- whole-program constant propagation where the value is proven immutable
- final peephole optimization after instruction selection

Whole-program optimization must be optional for debugging and profiling builds.
Disabling optimization must not change program results, only generated bytecode
shape and performance.

## Target-Specific Lowering

Target-specific optimization belongs after final AiBC bundle production unless
the target declares a separate object format. Target code may perform mechanical
lowering and packaging, but target packages must not redefine AiLang semantics.

Register allocation applies only to targets that lower AiBC into a register or
native-code representation. The portable AiBC bundle remains the canonical
language runtime artifact.
